CourseWise — storyboard

Assignment 2, Project Report · three interaction examples · every frame is a screenshot of the running system, not a mock-up
Storyboard 1 Stale document detected — the value changed
1 · Student asks
Action — one natural-language question. The student names neither the document nor the week, so the assistant has to find the right one and work out which version applies.
Control: Enter to send
2 · Answer, with the passage it came from
Response — the answer is the value from the version in force, and the passage it was taken from is attached, marked cited, with its section and date.
Control: click a passage to open the full excerpt
3 · The change is reported
Feedback — the warning names both values and the date of the replacement, and the superseded passage is still shown, so the student can see what they would otherwise have been told.
Control: the superseded passage stays visible, flagged
Storyboard 1 — out-of-date guidance. The student asks a question whose answer changed. The system answers from the version in force, shows the superseded version as flagged evidence, and states explicitly which value was replaced and when. This is the interaction that motivated the whole design: a student who missed the October announcement would otherwise have planned for a 90-minute paper.
Storyboard 2 The evidence boundary — answered, then declined
1 · Student asks
Action — a legitimate student question with a circumstance-based justification, of the kind the handbook is expected to address.
Control: Enter to send
2 · Answered, because the handbook covers it
Response — the answer comes from the FAQ, not from general knowledge. The student's own word "job" was mapped onto the handbook's term "work commitments".
Control: click the cited passage to read it in full
3 · Declined, because nothing covers it
Feedback — no passage matched, so the system refuses and says what was missing, rather than producing a plausible answer with no source. Refusal is a designed output, not an error.
Control: two suggested next steps are offered
Storyboard 2 — the evidence boundary. Frame 2 shows an answer that required mapping the student's vocabulary onto the handbook's. Frame 3 shows the harder case: the same interaction pattern produces a refusal with zero sources, because the corpus genuinely does not cover the question.
Storyboard 3 State change — propose, preview, confirm
1 · Student asks for an action
Action — a request that changes state, expressed informally with a day-part rather than a date.
Control: Enter to send
2 · System previews, changes nothing
Response — the preview names every field that would change, states the consequence and the cancellation rule, and offers a cancel path. Nothing is written yet.
Control: two explicit buttons — Confirm and Cancel
3 · After confirmation
Feedback — the outcome is stated in place of the preview, and the card can no longer be confirmed twice: the action id is single-use and a repeat returns HTTP 409.
Control: the booking is written to SQLite
Storyboard 3 — controlled state change. The assistant can only propose. The preview names every field that would change, states the consequence and the cancellation rule, and offers a cancel path that leaves state untouched. Only an explicit confirmation carrying the action id commits anything, and an action cannot be committed twice. The confirmation text still mentions an email, which no mail service delivers; that is labelled in the README as planned.
